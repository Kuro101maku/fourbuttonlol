# Tooltip — инструкция для сборки каждого нового обновления KuroAssistant

Используй этот документ как постоянную инструкцию при каждом новом обновлении приложения. Не переписывай workflow целиком и не создавай новую сборку с нуля, если существующий шаблон работает.

## Что делать при каждом новом обновлении

1. Найди в репозитории самый новый архив исходников `KuroAssistant_*.zip`, который пользователь загрузил для этого обновления. Не используй архив от предыдущей версии и не угадывай имя: проверь список файлов/коммитов. Если новый архив не найден, попроси пользователя загрузить его в репозиторий.
2. Возьми существующий рабочий workflow `.github/workflows/build-v28-apk.yml` как шаблон. Сохрани его структуру, настройки Gradle/Java, подпись, секреты, исправления совместимости, проверки и публикацию artifact. Не удаляй рабочие шаги и не заменяй файл без необходимости.
3. Измени только параметры версии/имени, которые должны отличаться:
   - имя workflow;
   - путь к новому ZIP в `on.push.paths` и команде `unzip`;
   - номер версии: `versionCode` — строго больше предыдущего; `versionName` — соответствует новой версии;
   - имя APK, имя artifact и текстовые подписи шагов;
   - имя выходного файла, чтобы оно точно соответствовало новой версии.
4. Сохрани package/application ID `com.example.fourbuttonpad` и используй те же GitHub Actions secrets для постоянной подписи: `KEYSTORE_BASE64`, `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD`. Не генерируй новый keystore и не публикуй секреты.
5. Если обновление требует поправить исходный код для сборки, вноси минимальные, точечные изменения и объясняй их. Не меняй поведение приложения без запроса пользователя.
6. Проверь workflow и исходники, затем запусти сборку через GitHub Actions (workflow_dispatch либо commit/push, если это поддерживается). Не говори, что сборка запущена, пока GitHub не подтвердит запуск.
7. Дождись завершения и проверь:
   - итог workflow — success;
   - все build/collect/upload шаги успешны;
   - artifact существует и не истёк;
   - APK присутствует, имеет ненулевой размер и корректно скачивается/распаковывается.
8. Скачай artifact и предоставь пользователю прямую ссылку на APK, а также ссылку на GitHub Actions run. Не утверждай, что APK установлен на телефон пользователя.
9. Если сборка не удалась, изучи лог конкретного упавшего шага, исправь причину минимально и повтори запуск. Не создавай бесконечные повторные запуски без анализа.
10. Не перемещай чаты между проектами и не утверждай, что переместил их, если нет доступного инструмента для такого действия.
